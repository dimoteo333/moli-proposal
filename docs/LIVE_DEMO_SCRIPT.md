# 몰리 공공제안 에이전트 — 라이브 편집 데모 (3분)

AI 코딩 에이전트(Claude Code)가 **시연 중 실시간으로 앱을 수정**하는 데모의 진행 대본입니다.
청중: 신한은행 제안 평가단. 목표 소요 시간: **약 3분** (본 시연 2분 30초 + 여유 30초).

---

## 1. 데모가 성립하는 원리

- 개발 서버(`npm run dev`)는 정적 파일을 **요청 시마다 디스크에서 다시 읽습니다.**
  소스를 수정하면 빌드·재시작 없이 **브라우저 새로고침 한 번**으로 반영됩니다.
- 데모에서 바꾸는 값은 전부 `src/app/data.js` 상단의 `demo` 블록과 그 아래 데이터에 모여 있고,
  `[LIVE-EDIT:*]` 주석 앵커가 붙어 있습니다. 에이전트에게 앵커 이름만 말하면 됩니다.

| 앵커 | 위치 | 바꾸면 일어나는 일 |
|---|---|---|
| `[LIVE-EDIT:live-toggle]` | `data.js` | LIVE 배지·데모 배너 표시/숨김 |
| `[LIVE-EDIT:eyebrow]` | `data.js` | 홈 히어로 상단 배지 문구 |
| `[LIVE-EDIT:banner]` | `data.js` | 데모 배너 제목·본문 |
| `[LIVE-EDIT:stats]` | `data.js` | 홈 지표 스트립 3종 |
| `[LIVE-EDIT:project]` | `data.js` | 사업명·발주기관·예산 (전 화면 반영) |
| `[LIVE-EDIT:requirements]` | `data.js` | 요구사항 추가 → 체크리스트·총 공수 자동 재계산 |
| `[LIVE-EDIT:email]` | `data.js` | 메일 초안 수신자·제목·본문 |
| 디자인 토큰 | `styles.css` `:root` | 브랜드 컬러 즉시 교체 |

## 2. 사전 준비 (시연 30분 전)

```bash
cd moli-proposal
git status                 # 작업 트리 클린 확인
git tag demo-start         # 복구 지점
npm test                   # 전체 게이트 통과 확인
npm run dev                # http://localhost:3000 (환경에 따라 포트 확인)
```

- 브라우저: `#home` 화면. 900px 이상 해상도면 폰 프레임 + 소개 패널이 함께 보입니다.
- 화면 배치: 왼쪽 절반 브라우저, 오른쪽 절반 Claude Code 터미널 —
  청중이 "요청 → 코드 수정 → 새로고침"을 한 화면에서 보게 합니다.
- **프롬프트 3개를 미리 복사해 둡니다** (아래 장면 1·2의 프롬프트). 타이핑 시간이 데모 시간입니다.
- 리허설: 장면 1을 한 번 실행 후 `git checkout -- src/app` 으로 원복해 둡니다.

## 3. 데모 흐름 (3분)

### 장면 0 — 오프닝 (30초, 수정 없음)

홈 화면을 보여주며:

> "몰리는 공공 RFP를 읽고 근거와 공수까지 정리하는 워크벤치입니다.
> 지금 보시는 건 영상이 아니라 실행 중인 실제 코드고, 옆의 AI 에이전트가
> 이 자리에서 직접 수정합니다. 바로 보여드리겠습니다."

말하는 동안 Claude Code에 장면 1 프롬프트를 붙여넣고 실행해 둡니다.

### 장면 1 — 문구 실시간 편집 (45초)

```text
src/app/data.js 의 [LIVE-EDIT:eyebrow] 앵커 문구를
"신한은행 제안 평가단 여러분, 환영합니다"로 바꿔줘.
```

새로고침 → 히어로 배지가 바뀝니다.

> "방금 에이전트가 소스 코드를 직접 고쳤습니다. 빌드도 배포도 없습니다."

### 장면 2 — 요구사항 추가와 자동 재산정 (75초, 하이라이트)

말하는 동안 미리 실행해 둔 프롬프트:

```text
src/app/data.js 의 [LIVE-EDIT:requirements] 배열 끝에 요구사항을 추가해줘:
id "r11", 제목 "관제사 모바일 알림 앱 (제안 아이템)", type "제안 아이템",
mandatory false, mm min 1.5 / recommended 2.5 / max 3.5,
role은 pm 0.2, backend 0.8, frontend 1.2, qa 0.3,
confidence 0.7, risk "low", recommendation "recommend",
reason "현장 관제사의 야간 대응 속도를 높이는 차별화 항목",
evidence 빈 배열, packages S false / M true / L true.
```

새로고침 → 체크리스트 화면(`#checklist`)으로 이동:

- 항목 수가 10 → 11로 늘어난 것
- Medium 총 공수가 자동으로 늘어난 것 (하단 합계 바)

> "데이터 한 건을 추가했을 뿐인데 체크리스트와 총 공수, 패키지 비교까지 전부
> 재계산됐습니다. 프로토타입이 아니라 구조를 갖춘 제품이라는 뜻입니다."

### 장면 3 — 마무리 (30초)

```text
[LIVE-EDIT:live-toggle] 의 live 를 false 로 바꿔줘.
```

새로고침 → LIVE 배지·데모 배너가 사라지고 정식 서비스 화면이 됩니다.

> "데모 모드를 끄면 이대로 제안 검토에 쓸 수 있는 화면입니다. 감사합니다."

### 예비 장면 (질문이 나오면, +60초)

신한 블루 테마 전환 — CI 적용이 토큰 세 줄이라는 것을 보여줄 때:

```text
src/app/styles.css 의 :root 에서 --color-primary 를 #0046ff,
--color-primary-pressed 를 #0036c7, --color-primary-soft 를 #eaf0ff 로
바꿔서 신한 블루 테마로 전환해줘.
```

원복: `몰리 바이올렛(#6b4eff / #5438e6 / #efecff)으로 되돌려줘.`

## 4. 복구 및 안전장치

| 상황 | 조치 |
|---|---|
| 장면 하나만 되돌리기 | 에이전트에게 "방금 수정 원복해줘" 요청 |
| 전체 초기화 | `git checkout demo-start -- src/app` 후 새로고침 |
| 에이전트 응답 지연 | 위 프롬프트 값을 직접 타이핑해 수동 편집 (모든 장면은 `data.js` 단일 파일 수정) |
| 화면이 깨졌을 때 | `git checkout -- src/app/data.js` 가 최속 복구 |
| 서버 다운 | `npm run dev` 재실행 (상태는 파일 기반이라 손실 없음) |

시연 종료 후: `git checkout demo-start -- src/app && git tag -d demo-start`

## 5. 타이밍 요약

| 장면 | 내용 | 누적 |
|---|---|---|
| 0 | 오프닝 + 프롬프트 선실행 | 0:30 |
| 1 | 문구 편집 | 1:15 |
| 2 | 요구사항 추가 + 자동 재산정 | 2:30 |
| 3 | 데모 모드 종료 | 3:00 |
