# 문서 품질 개선 계획

## 목표

실제 RFP, 과업지시서, 제안요청 첨부 파일을 올렸을 때 분석 결과가 샘플 fixture 수준으로 안정적으로 나오도록 문서 품질 파이프라인을 강화한다.

## 품질 단계

1. 수집: 업로드 파일의 확장자, 크기, 체크섬, 페이지 수, 암호화 여부를 기록한다.
2. 1차 파싱: 텍스트 추출이 가능한 파일은 결정적 파서로 블록, 표, 문단, 페이지 앵커를 만든다.
3. OCR 보강: 스캔 이미지, 깨진 표, 다이어그램은 GLM Vision 보강 후보로 분리한다.
4. 구조화: 일정, 제출물, 보안, 인력, 평가, 계약 조건을 요구사항 후보로 정규화한다.
5. 근거 검증: 모든 요구사항은 원문 quote, page, block id, confidence를 가진다.
6. 사람 검토: 근거가 약하거나 AI가 보강한 요구사항은 보고서 확정 전에 검토 플래그를 남긴다.

## 품질 지표

| 지표 | 목표 |
| --- | --- |
| 파싱 성공률 | 정상 PDF/DOCX/HWPX 기준 95% 이상 |
| 근거 앵커 보유율 | 보고서 반영 요구사항 100% |
| 낮은 confidence 비율 | 운영 초기 20% 이하로 추적 |
| AI 보강 폴백률 | 장애 시 결정적 파이프라인 유지 |
| 보고서 수동 수정률 | Preview 배포에서 샘플별 추적 |

## 운영 저장 필드

Supabase에는 원문 파일, 파싱 블록, evidence refs, requirements, reports, audit events를 분리해 저장한다. OCR 이미지는 Supabase Storage에 저장하고 DB에는 storage path와 checksum만 둔다.

## GLM 적용 범위

GLM은 원문 파서를 대체하지 않는다. GLM은 누락 가능성이 큰 블록을 보강하고, 요구사항 표현을 정리하고, 한국어 보고서의 문장 품질을 높이는 보조 계층이다.

Vision MCP Server는 로컬 QA와 운영 조사에 먼저 사용한다. 운영 사용자 요청 처리 경로는 서버 측 GLM Vision API 어댑터로 분리해 Vercel/Supabase 배포 특성에 맞춘다.
